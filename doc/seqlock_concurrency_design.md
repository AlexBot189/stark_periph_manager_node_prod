# 并发数据读写方案对比

## 背景

传感器缓存（IMU / 足底压力 / 气压计）的典型场景：**后台线程写数据，RT 控制线程读数据**，单生产者单消费者（SPSC），读者只关心「最新一帧完整数据」。

要解决的核心问题只有一个：**读者读数据时，写者不能同时改写同一块内存**（撕裂）。

## 四种方案

### 1. 互斥锁（mutex）

写者/读者都用同一把锁保护缓存。

```c
// 读者
pthread_mutex_lock(&m_mutex);
memcpy(out, &m_cached, sizeof(m_cached));
pthread_mutex_unlock(&m_mutex);
```

- 优点：简单、易验证、无撕裂
- 缺点：RT 线程抢锁时若被后台线程持锁，会 futex 阻塞（µs~ms），有优先级反转风险，可能漏 RT 截止期
- 耗时：无竞争 ~12ns，竞争时 µs~ms

### 2. 双 buffer + 原子索引

两块 buffer + 一个原子索引。写者写「非活跃」块后翻转索引，读者读「活跃」块。

```c
// 写者
int w = m_idx.load(relaxed) ^ 1;
m_buf[w] = data;
m_idx.store(w, release);
// 读者
int r = m_idx.load(acquire);
*out = m_buf[r];
```

- 优点：无锁、无重试
- 缺点：**理论撕裂**。读者在「读索引」和「拷数据」之间若被抢占，写者绕两圈（0→1→0）会覆盖读者正读的块
- 撕裂概率极低（需读者被抢占时长 ≈ 写者 2 个周期），后果是单帧数据不一致，best-effort 可容忍
- 现有 SHM `fb_buffer[2] + active_idx` 即此方案

### 3. 三 buffer

三块 buffer + 两个原子索引（最新块 + 读者正在读的块）。写者避开读者正在读的块，读者永不重试。

- 优点：无锁、**严格无撕裂、零重试、延迟严格有界**
- 缺点：3 倍内存、2 个原子、读者要多一次「宣布在读哪块」的 store，逻辑更绕

### 4. Seqlock（顺序锁）

一块 buffer + 一个序号。写者写前把序号变奇数、写后变偶数；读者读前后各读一次序号，不一致就重读。

```c
// 写者
uint32_t s = m_seq.load(relaxed);
m_seq.store(s + 1, release);   // 奇数 = 写中
m_data = data;
m_seq.store(s + 2, release);   // 偶数 = 写完

// 读者
uint32_t s1, s2;
do {
    s1 = m_seq.load(acquire);
    *out = m_data;
    s2 = m_seq.load(acquire);
} while (s1 != s2 || (s1 & 1));   // 序号变或奇数 → 撞上写者 → 重读
```

- 优点：无锁、**严格无撕裂**（撕裂就重读）、内存最省（1 块 + 1 原子）、逻辑简单
- 缺点：读者可能重试。重试概率 = 写者「写中」时间占比，气压计 20Hz 写约 2e-7，足压 1000Hz 写约 1e-5，实际等价于不重试
- Linux 内核标准原语（seqlock_t）

## 对比总表

| 维度 | mutex | 双 buffer | 三 buffer | seqlock |
|---|---|---|---|---|
| 无撕裂 | ✅ | ⚠️ 理论撕裂 | ✅ | ✅ |
| 读者重试 | 无 | 无 | 无 | 概率≈0 |
| 优先级反转 | ⚠️ 有 | 无 | 无 | 无 |
| 读者耗时 | ~12ns / 竞争µs~ms | ~7ns | ~7ns | ~7ns |
| 延迟确定性 | 差 | 确定 | 严格确定 | 近似确定 |
| 内存 | 1 块 | 2 块 | 3 块 | 1 块 |
| 原子变量 | 0 | 1 | 2 | 1 |
| 复杂度 | 低 | 低 | 中 | 低 |

## 结论

采用 **seqlock**：

1. 严格无撕裂、无优先级反转、无阻塞，满足量产稳定性要求
2. 内存最省、逻辑最简单，和 mutex 改动量相当
3. 重试概率 1e-5 ~ 1e-7，实际等价于不重试，不影响 RT 确定性
4. 是内核成熟原语，非自造轮子

## 实现约定

- 序号用 `std::atomic<uint32_t>`，写者 release、读者 acquire（禁用 seq_cst）
- 数据块用 POD 结构体（现有 `imu_data_t` / `foot_pressure_data_t` / `barometer_data_t` 均为 POD）
- 严格单生产者单消费者：每个缓存只有一个写者（后台线程）、一个读者（RT 线程）
